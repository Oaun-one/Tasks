# gen-g780 — real-estate fair-housing collateral audit

**Task ID** NONC-B1-1001608 · ComputerBench NonConnector · offline, no connectors
**Oracle** 1.0 (46/46) · **GLM-5.2** 5/5 · **Status: too easy — see below**

## What the task asks

A seller's book is going to print. The agent audits its section inventory against the
brokerage's fair-housing standard RE-FH-9 — including its 2026 amendments — then
delivers `fairhousing_audit.csv` (two columns, one row per section), `fairhousing_memo.md`,
and `results.json` with five section counts.

## What changed from the mined baseline, and why

**The baseline was a rename, not an audit.** `seller_book_sections.csv` shipped with columns
`contains_personal_narrative`, `mentions_protected_class_terms`, `is_mandated_disclosure`,
`missing_required_disclaimer` — a 1:1 map onto the four output labels, with no section text
at all. In the first battery **4 of 5 runs echoed that header with a `finding` column
appended**. There was nothing to judge.

Changes, in the order they were made:

1. **Verifiers rebuilt (14 → 46).** The original grader passed a knowingly wrong answer:
   `mandated_trap_clean` was `^SEC-04\s*,.*none`, which scans the whole row, so a deliverable
   that flagged SEC-04 and added a rationale column containing "none" scored 14/14. SEC-07 —
   the only multi-finding row — had no verifier at all, and `memo_finding_terms` was
   `(?i)\bA|\bB|\bC`, which passes on any one term. Row checks are now end-anchored, with
   negative guards on the trap sections.
2. **Prompt rewritten.** Removed its own trap announcement ("mind the standard's exception"),
   pinned the CSV schema and the `|` join order, and defined all five counts as counts of
   *sections* — `flagged_count` and `protected_lang_count` were graded but never defined.
3. **Fixtures replaced with real collateral.** 30 sections of actual marketing copy with a
   `role` column. The agent now has to read prose and judge it.
4. **Standard amended.** RE-FH-9 §5 carries this year's changes: §5a adds *marital status*
   and *source of income* to the required disclosure (9 → 11 classes); §5b brings `agent_bio`
   into §4 scope. Both must be applied; §5 governs where it conflicts with §§2–4.

Gold and inventory are generated by the same script, so they cannot drift apart.

## Why the task is non-trivial

Correctness depends on a **chained derivation**: the required class list must be assembled
from RE-FH-9 §2 *plus* the §5 amendments, then used as a filter on every notice in the book.

That makes the surface signals actively misleading:

| Section | Reads as | Actually |
|---|---|---|
| SEC-04 `disclosure_block`, 9-class notice | the safe one — it *is* the disclosure | `PROTECTED_CLASS_LANGUAGE` — stale under §5a, so no §3 exemption |
| SEC-10 `closing_page`, 11-class notice | 11 protected-class terms → flag it | `none` — complete, so exempt and §4 satisfied |
| SEC-21 `agent_bio`, no notice | out of §4 scope | `DISCLAIMER_MISSING` — §5b brought it in |

Miss §5 and you get a confidently wrong answer across many rows and all five
counts at once, not one cell.

## Grading

46 verifiers, **all deterministic — no LLM judge**, so the verdict is fully reproducible.
`tests/test.sh` is binary: reward 1 only if every verifier passes, so always-passing checks
cannot inflate a partial score.

Five Oracle repeats under `evaluations/stability/` all score 1.0 with identical verdicts.

## Why it is marked too easy

Eight batteries against successive versions of the task. The shipped version scores 5/5;
`evaluations/` contains that battery and nothing else. One earlier, superseded version scored
4/5 — that battery is not part of this bundle and is described below only as evidence of what
was tried.

Hardening used every mechanism the onboarding doc names — coupled reasoning, cross-source
synthesis, chained derivation, state across steps, data-shape sabotage — at the shape of its
own example task (30 items, multi-source reconciliation).

The single failing run is the most informative evidence here, and it was a genuine model
error rather than infrastructure: a clean stop at 15 steps with all deliverables written and
42 of 46 verifiers passing. It marked one `agent_bio` section clean when that section carried
a stale notice, and each of the three derived counts came out exactly one low. It had applied
§5b correctly to a bare `agent_bio` in the same run, so the amendment was understood and then
applied inconsistently.

The next version raised that family from one member to five. All five runs on that version
scored 1.0, which identifies the earlier miss as variance rather than a reproducible gap. The
shipped version reproduces that result. Trajectories
confirm the model reads the §5 amendments, derives the eleven-class list and flags the stale
`disclosure_block` correctly.

Estimated per-run pass probability is around 0.9. That is above the ≤3/5 band and there is no
remaining lever that does not either leave the topic or manufacture ambiguity. Recorded as
**too easy** and the row retained, per delivery guidance.

One run in an earlier battery was excluded as invalid: it truncated at the reasoning-token
ceiling (`"reason":"length"`, zero output, no deliverables). The battery config now sets
`max_tokens: 96000`.

  `OracleAgent` writes only `agent/oracle.txt`; it does not emit trajectories.
